# ADR 0005: Образ приложения на Python 3.12 slim с uv

**Статус:** принято  
**Дата:** 2026-05-04

## Контекст

В [vision.md](../vision.md) (§10) для MVP зафиксированы: один `Dockerfile` в корне на базе официального **Python 3.12** (slim), установка зависимостей через **uv**, копирование `src/` и метаданных проекта, переменные окружения снаружи образа (`--env-file`), цели `make docker-build` / `make docker-run`.

## Решение

- Базовый образ: `python:3.12-slim`.
- Бинарники **uv** копируются из официального distroless-образа Astral: `COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/` — как в [документации uv](https://docs.astral.sh/uv/guides/integration/docker/) (включён `uvx` в ту же целевую директорию).
- Установка окружения: два этапа `uv sync --frozen` — сначала только транзитивные зависимости проекта (`--no-install-project`) по `pyproject.toml` и `uv.lock`, затем копирование `src/` и `README.md` (нужен для поля `readme` в `pyproject.toml` при сборке метаданных), второй `uv sync --frozen` устанавливает сам пакет **aidd**.
- Режим без dev-зависимостей: `ENV UV_NO_DEV=1` (эквивалент `--no-dev`).
- Точка входа: `ENTRYPOINT ["uv", "run", "python", "-m", "aidd"]` — совпадает с локальным запуском.
- Файл `.env` в образ не копируется; в контекст сборки исключён через [`.dockerignore`](../../.dockerignore) вместе с `.venv`, чтобы не тащить локальное venv и секреты.

## Последствия

- Сборка воспроизводима при неизменном `uv.lock`.
- Первый слой `RUN uv sync ... --no-install-project` кешируется при неизменных зависимостях, даже если меняется только код в `src/`.
- Тег `ghcr.io/astral-sh/uv:latest` не закреплён по digest — для жёсткой воспроизводимости CI позже можно зафиксировать версию или SHA (см. документацию uv).
