#### Детальный анализ

**Эксперимент 1 — chunk_size=1500, chunk_overlap=150 (132 чанка)**

*Q1 (кредит):* Структурированный ответ из 6 пунктов с охватом всего жизненного цикла кредита (договор, стороны, обеспечение, заключение, погашение). Хорошая полнота, но местами обобщённо — нет конкретных цифр ставки/срока.

*Q2 (вклады):* Ответ описывает механизм расчёта ставки через «пороговое значение», но без конкретных цифр и перечня продуктов. Меньше деталей, чем в последующих экспериментах.

**Оценка:** Большой чанк охватывает широкий контекст, но «разбавляет» точную информацию — ответы полные, но менее конкретные.

---

**Эксперимент 2 — chunk_size=800, chunk_overlap=100 (246 чанков)**

*Q1 (кредит):* Лучший ответ из трёх — 5 структурированных пунктов с упоминанием конкретного закона (№ 353-ФЗ), ПСК, сторон (Сбербанк), графика платежей. Баланс полноты и конкретики.

*Q2 (вклады):* Перечислены конкретные продукты («Лучший % Лидер», «Лучший % Премьер», «Сбер Рядом» и др.), указаны страницы документа (11–12), объяснён принцип расчёта. Значительно лучше Эксперимента 1.

**Оценка:** Оптимальный баланс. Чанк достаточно велик, чтобы сохранять смысловой контекст, и достаточно мал, чтобы векторный поиск находил точные фрагменты.

---

**Эксперимент 3 — chunk_size=500, chunk_overlap=50 (377 чанков)**

*Q1 (кредит):* Ответ короче и менее детальный — 3 пункта вместо 5–6. Упоминается закон № 353-ФЗ, но пропали пункты про обеспечение, порядок заключения, порядок погашения. Малый чанк «разрезал» связные разделы.

*Q2 (вклады):* Самый полный перечень продуктов из трёх экспериментов — перечислены 8 наименований вкладов. Для коротких, терминологически насыщенных фрагментов (списки тарифов) малый чанк работает лучше.

**Оценка:** Хорош для поиска по спискам/тарифам, но теряет смысловую связность для сложных структурированных разделов.

---

#### Выводы

1. **Оптимальный размер — chunk_size=800, chunk_overlap=100.** Даёт лучший ответ по Q1 (кредит) и сильный по Q2 (вклады). Overlap ~12% от размера чанка — достаточен для сохранения контекста на границах.

2. **Большие чанки (1500)** дают широкий контекст, но снижают точность поиска — релевантный фрагмент «тонет» в большом куске текста.

3. **Малые чанки (500)** эффективны для тарифных таблиц и перечней, но дробят связные нарративные разделы (условия кредита), что ухудшает полноту ответа.

4. **Overlap:** при chunk_size=500 overlap всего 50 (10%) недостаточен — предложения на границах чанков теряются. При 1500/150 overlap слишком мал относительно размера (10%). При 800/100 (~12%) — баланс оптимален.

5. **Рекомендация для следующих экспериментов:** попробовать `separators=["\n\n", "\n", ". "]` с chunk_size=800 для более семантически корректных разбивок по абзацам.

#### Результаты (13.05.2026, один и тот же индекс: PDF + JSON, ~544 чанка, `RETRIEVER_K=3`)

Скрипт строит `InMemoryVectorStore` трижды для моделей ниже и печатает top-k документов по тем же запросам, что в боте.

| Модель | ID для `.env` | ~цена OpenRouter | Q1 Условия потребительского кредита? | Q2 Проценты по вкладам? | Q3 Как заказать карту? |
|--------|---------------|-----------------|---------------------------------------|--------------------------|-------------------------|
| Baseline | `openai/text-embedding-3-large` | $0.13/M | ✅ Top: PDF `ouk_potrebitelskiy_kredit_lph.pdf` (общие условия кредита) | ✅ Top: PDF `usl_r_vkladov.pdf` (тарифы/«Лучший %» и т.п.) | ⚠️ Top: смежные JSON по дебетовым картам (FAQ тот же хаб); не всегда «Как заказать» в топ-3 |
| BAAI bge-m3 | `baai/bge-m3` | $0.01/M | ❌ FAQ кредитных **карт** (JSON ccards_faq), не PDF ОУ | ❌ FAQ карт вообще («сколько лет…»), не вклады PDF | ✅ JSON дебетовые карты/debet_cards FAQ (в т.ч. про заказ) |
| Qwen3 8B | `qwen/qwen3-embedding-8b` | $0.01/M | ❌ FAQ карт/street card (JSON ccards_faq), не ОУ вклада/кредита | ❌ JSON по картам («досрочно погасить баллы» и т.д.), не PDF вкладов | ⚠️ Смесь ccards FAQ; только на 3-й позиции точное «Как оформить карту» из JSON |

#### Выводы

1. **На смешанном корпусе (длинные PDF + короткий JSON‑FAQ)** дешёвые multilingual‑модели на запросах с словами «кредит» / «проценты» чаще тянут релевантные по теме карты FAQ, чем нужные страницы PDF вкладов/потребкредита. **Baseline (`text-embedding-3-large`) однозначно лучше по Q1/Q2 retrieval** в этом прогоне.
2. **Экономика:** `baai/bge-m3` и `qwen/qwen3-embedding-8b` — ~**в 13 раз дешевле** baseline (~$0.01/M против ~$0.13/M при проверке OpenRouter Pricing). Имеет смысл оставить их кандидатами при добавлении **rerankера**, **фильтра по источнику** (метаданные `source`/`category`) или раздельных индексов.
3. **Рекомендация для текущего бота без доработок цепочки:** оставить **`EMBEDDING_MODEL=openai/text-embedding-3-large`** для стабильного ответа по PDF; при переходе на дешёвые эмбеддинги — обязательна повторная оценка RAG после mitigations.

**Повторить эксперимент:** см. пример переменных в [`env.example`](env.example); запуск скрипта из корня: `uv run python scripts/hw3_compare_embeddings.py` (вывод см. терминала; нужен валидный `OPENAI_API_KEY` и `OPENAI_BASE_URL` для OpenRouter).
