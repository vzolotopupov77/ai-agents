## Итеративный план

### Итерация 1 — Telegram и первый сквозной диалог через LLM

**Цель итерации:** бот в личном чате через long polling получает текст пользователя и возвращает ответ, собранный моделью с учётом системной роли из конфигурации.

- [x] Репозиторий и запуск приложения локально из документации проекта.
- [x] Настройки из окружения (токены, endpoint и параметры модели — по vision).
- [x] Long polling к Telegram и обработка входящего текста.
- [x] Вызов LLM по конфигурации; запрос: системная роль + текущая реплика пользователя.
- [x] Ручная проверка: вопрос в чат → осмысленный ответ.

**Готово, если (DoD)**

**Самопроверка**

- [x] Процесс стартует без падений при валидном `.env`.
- [x] В stderr — ожидаемые записи журнала, без секретов.
- [x] На тестовый вопрос приходит финальный ответ ассистента; нет необработанного исключения в цепочке.

**Пользователь**

- [x] На произвольный текст в личке приходит ответ от бота (ответ строится моделью, не заглушка приложения).
- [x] Ответ по смыслу согласован с заданной ролью и формулировкой вопроса.

### Итерация 6 — Финансовый советник: модель учёта и `/report`

Извлечение операций из текста **ещё не** делается.

### Итерация 7 — Structured output из текста

**Цель итерации:** сообщения пользователя о тратах и доходах разбираются LLM с **structured output**; при **`found=True`** создаётся `Transaction` и отправляется подтверждение; при **`found=False`** — ответ советника без записи (см. vision §6, §7).

- [x] Pydantic-схема извлечения (`TransactionExtract`); вызов Chat Completions с `response_format: json_object`, парсинг JSON (`parse_transaction_extract_json`), суффикс системному промпту под формат и неясные суммы.
- [x] Интеграция в обработчик текста: запись в хранилище при успешной сборке `Transaction`, единое обновление истории для found=True/False; подтверждение записи формируется из данных учёта (`format_transaction_confirmation`).
- [x] Ручная проверка: фразы с суммой и без; граничные случаи (в т.ч. неоднозначная сумма после правок кода); дубликаты записей при сомнительных формулировках — по возможности просмотрены.

**Готово, если (DoD)**

**Самопроверка**

- [x] При сбое extract (сеть/API, неразборчивый JSON, пустое тело completion без `choices`) — нейтральное сообщение пользователю; успешная пара user/assistant в историю не добавляется. Отдельный повтор сценария ит.3 с неверным `OPENROUTER_API_KEY` в рамках ит.7 не фиксировался (обработчик тот же класс исключений).

**Пользователь**

- [x] Типичная трата/доход в одном сообщении отражается в `/report`; сообщение без операции не создаёт запись; граничные случаи проверены; найденные дефекты исправлены и перепроверены.
