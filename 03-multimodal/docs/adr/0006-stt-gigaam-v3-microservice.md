# ADR 0006: Транскрибация голосовых сообщений через GigaAM-v3 (HTTP-микросервис)

**Статус:** принято  
**Дата:** 2026-05-12

## Контекст

Требуется транскрибация голосовых сообщений Telegram (формат `.ogg/opus`) в текст для последующей передачи в LLM-pipeline финансового советника.

Рассматривались следующие подходы:

| Вариант | Качество RU | Стоимость | Сложность |
|---------|-------------|-----------|-----------|
| OpenAI Whisper API | хорошее (WER ~8–12%) | $0.006/мин, нет free tier | минимальная |
| AssemblyAI | хорошее | 185 ч бесплатно, затем $0.15/ч | низкая |
| Yandex SpeechKit | отличное | ~10 ₽/мин, IAM-токены | средняя |
| faster-whisper large-v3 (локально) | хорошее (WER ~8%) | $0 | средняя |
| **GigaAM-v3 (Sber, MIT, локально)** | **SOTA для RU (WER 2.6–3.9%)** | **$0** | средняя |
| Vosk | плохое (WER ~33%) | $0 | низкая |

Проект уже использует GPU-сервер `195.209.210.184` с RTX 4090 (23 GB VRAM) для Ollama. GigaAM-v3 занимает ~1–2 GB VRAM, не конкурирует с загруженными LLM-моделями.

## Решение

Выбран **GigaAM-v3** (открытая SOTA-модель от Sber/SaluteDevices, MIT-лицензия) как отдельный **FastAPI HTTP-микросервис** на том же GPU-сервере.

- Микросервис (`stt_service/`) живёт в корне репозитория, деплоится вручную через SSH на `195.209.210.184:8765`.
- Бот обращается к нему через `SttClient` (async HTTP, `httpx`) по адресу из переменной окружения `STT_BASE_URL`.
- `STT_BASE_URL` — опциональная переменная: если не задана, голосовые сообщения отклоняются с понятным сообщением пользователю, бот продолжает работу.
- Аудио конвертируется на стороне STT-сервиса (`ffmpeg`/`pydub`): `.ogg` → `wav` 16 kHz mono.
- Используется модель `ai-sage/GigaAM-v3` (e2e_ctc — с пунктуацией и нормализацией текста).

## Последствия

- Бот и STT-сервис — независимые процессы: перезапуск бота не затрагивает STT.
- STT-сервис не входит в основной Docker-образ бота (`src/aidd/`); деплоится отдельно на GPU-сервере.
- При недоступности STT-сервиса (сеть, сбой) голосовые сообщения не обрабатываются, текстовый и фото-режимы работают штатно.
- GigaAM-v3 скачивает веса (~1 GB) с HuggingFace при первом запуске; при повторных стартах — из локального кеша.
- **Пакет `gigaam` с PyPI** на момент внедрения **не содержал** имён моделей v3; в проде ставим **`gigaam` из GitHub** (см. [stt_service/README.md](../../stt_service/README.md)) и фиксируем **PyTorch + CUDA** (`cu124`), т.к. `pip install -r requirements` может перетянуть CPU-сборку `torch`.
- UFW на сервере неактивен — порт 8765 доступен сразу после запуска сервиса; при ужесточении безопасности порт можно закрыть и использовать SSH-туннель.
