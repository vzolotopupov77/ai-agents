# ADR 0006: Транскрибация голосовых сообщений через GigaAM-v3 (HTTP-микросервис)

**Статус:** принято  
**Дата:** 2026-05-12

## Контекст

Требуется транскрибация голосовых сообщений Telegram (формат `.ogg/opus`) в текст для последующей передачи в LLM-pipeline финансового советника. Проект уже использует GPU-сервер `195.209.210.184` (RTX 4090, 23 GB VRAM, CUDA 13.2) для Ollama.

---

## Рассмотренные варианты

### 1. OpenAI Whisper API / GPT-4o Transcribe

**Плюсы:**
- Минимальная интеграция — один HTTP-запрос, официальный Python SDK.
- 99+ языков, русский поддержан стабильно.
- Нет своей инфраструктуры и зависимости от GPU-сервера.
- Модель `gpt-4o-mini-transcribe` — самая дешёвая из облачных ($0.003/мин).

**Минусы:**
- Нет бесплатного уровня — платно с первой минуты.
- Данные уходят на серверы OpenAI (США); потенциальные ограничения для финансовых данных.
- Зависимость от внешней сети и доступности API (429, таймауты).
- WER для русского ~8–12% — заметно хуже GigaAM-v3.
- Лимит файла 25 MB; длительные голосовые требуют разбивки.

**Стоимость:** $0.003–$0.006/мин (нет free tier)  
**WER RU:** ~8–12%  
**Сложность интеграции:** минимальная

---

### 2. AssemblyAI

**Плюсы:**
- Щедрый бесплатный уровень: 185 часов транскрибации.
- Удобный Python SDK, хорошая документация.
- Поддержка русского в модели Universal-2.
- Дополнительные функции: диаризация, резюме, sentiment.

**Минусы:**
- Модель Universal-3 (новейшая, лучшего качества) **не поддерживает русский** — только 6 языков.
- Для русского придётся использовать Universal-2, качество ниже конкурентов.
- Данные уходят на серверы AssemblyAI (США).
- После исчерпания free tier: $0.15/ч ($9/мин × 100 мин — нет, $0.15/ч это $0.0025/мин).
- Зависимость от внешнего сервиса.

**Стоимость:** 185 ч бесплатно → $0.15/ч  
**WER RU:** приемлемое (Universal-2), без точных публичных цифр  
**Сложность интеграции:** низкая

---

### 3. Yandex SpeechKit

**Плюсы:**
- Специализирован на русском языке — одно из лучших коммерческих решений для RU.
- Стриминговое распознавание в реальном времени.
- Хорошая точность на разговорной речи, акцентах, профессиональной лексике.

**Минусы:**
- Требует Yandex Cloud аккаунт, IAM-токены, управление сервисными аккаунтами.
- Цена непрозрачна: биллинг в рублях за сегменты по 15 сек; данные на серверах Яндекса.
- Интеграция сложнее, чем у OpenAI или AssemblyAI (gRPC или REST с IAM).
- Доступность из-за рубежа потенциально ограничена.
- Нет официального async Python-клиента для STT.

**Стоимость:** ~10–15 ₽/мин в deferred-режиме, дороже в realtime  
**WER RU:** SOTA коммерческий уровень  
**Сложность интеграции:** средняя–высокая

---

### 4. faster-whisper large-v3 (локально на GPU-сервере)

**Плюсы:**
- Бесплатно — сервер уже оплачен.
- 4× быстрее оригинального `openai/whisper` (CTranslate2 backend).
- На RTX 4090: ~30–50× realtime (large-v3, fp16).
- Данные не покидают сервер — полная приватность.
- Есть fine-tuned вариант под русский: `bzikst/faster-whisper-large-v3-russian`.
- Простая интеграция через Python-пакет `faster-whisper`.

**Минусы:**
- WER для русского ~7–8% — существенно хуже GigaAM-v3 (2.6–3.9%).
- Нет встроенной пунктуации и нормализации (нужно добавлять постпроцессинг).
- Модель large-v3 занимает ~3 GB VRAM.
- Потребует той же инфраструктуры HTTP-микросервиса, что и GigaAM.

**Стоимость:** $0  
**WER RU:** ~7–8% (large-v3), ~3% с fine-tune  
**Сложность интеграции:** средняя

---

### 5. Vosk

**Плюсы:**
- Полностью офлайн; модели от 50 MB.
- Работает на CPU без GPU.
- Очень лёгкий, встраивается напрямую в процесс бота.

**Минусы:**
- WER для русского ~33% — неприемлемое качество для финансового контекста.
- Отстаёт от современных нейросетевых моделей на несколько поколений.
- Плохо справляется с разговорной речью, именами, суммами.

**Стоимость:** $0  
**WER RU:** ~33%  
**Сложность интеграции:** минимальная  
**Вывод:** отклонён из-за качества

---

### 6. GigaAM-v3 (Sber / SaluteDevices, MIT)

**Плюсы:**
- **SOTA для русского языка**: WER 2.6–3.9% (лучше Whisper large-v3 на ~50%).
- Обучена на 700 000 часов русской речи, включая голосовые сообщения и разговорный стиль.
- MIT-лицензия, полностью open-source — данные остаются на сервере.
- Вариант `v3_e2e_ctc` — end-to-end модель с пунктуацией и нормализацией текста «из коробки».
- ~1–2 GB VRAM — не конкурирует с Ollama на RTX 4090.
- Активно поддерживается (последнее обновление апрель 2026).

**Минусы:**
- Только русский язык (и частично смешанная речь).
- Нативная поддержка аудио файлов через `gigaam` — фрагменты **до ~25 секунд**; длинные голосовые требуют `transcribe_longform` (доп. зависимость `pyannote`).
- Пакет `gigaam` на PyPI (v0.1.0) **не содержит** имён моделей v3 — установка через GitHub.
- После `pip install -r requirements.txt` пакет `gigaam` может перетянуть CPU-сборку PyTorch — требует ручного `pip install torch+cu124` после.
- Требует NeMo-совместимый стек (hydra, omegaconf, sentencepiece) — тяжелее, чем у Whisper.

**Стоимость:** $0  
**WER RU:** 2.6–3.9% (e2e_ctc / e2e_rnnt)  
**Сложность интеграции:** средняя

## Решение

Выбран **GigaAM-v3** (`v3_e2e_ctc`) как отдельный **FastAPI HTTP-микросервис** на том же GPU-сервере (`195.209.210.184:8765`).

- Микросервис (`stt_service/`) живёт в корне репозитория, деплоится вручную через SSH.
- Бот обращается к нему через `SttClient` (`httpx`) по адресу из переменной `STT_BASE_URL`.
- `STT_BASE_URL` — **опциональная** переменная: без неё голосовые сообщения отклоняются, бот работает штатно.
- Конвертация `.ogg` → WAV 16 kHz mono — на стороне STT-сервиса (`pydub` + `ffmpeg`).

## Последствия

- Бот и STT-сервис — независимые процессы: перезапуск бота не затрагивает STT.
- STT-сервис не входит в Docker-образ бота; деплоится отдельно на GPU-сервере.
- При недоступности STT голосовые сообщения не обрабатываются, текст и фото работают штатно.
- GigaAM-v3 скачивает веса (~420 MB энкодер + ~235 KB конфиг) с HuggingFace при первом запуске; при повторных стартах — из локального кеша (`~/.cache/huggingface`).
- **Ограничение длины:** `.transcribe()` рассчитан на фрагменты до ~25 секунд. Длинные голосовые (>25 сек) возвращают пустой или обрезанный результат — в MVP не обрабатываются; пользователь получает нейтральный ответ.
- **Установка:** `gigaam` с PyPI (v0.1.0) не содержит моделей v3 — ставится из GitHub. После `pip install -r requirements.txt` PyTorch может быть заменён CPU-сборкой; нужен явный `pip install torch==2.5.1+cu124 --index-url …/cu124` (задокументировано в [stt_service/README.md](../../stt_service/README.md)).
- UFW на сервере неактивен — порт 8765 публичен после старта сервиса; при ужесточении безопасности закрыть и использовать SSH-туннель.
