Развиваем проект до автономного ReAct агента банковсого обслуживания клиентов.
Агент должен обладать инструментом:
- rag_search - использует текущие варианты ритриверов (semantic/hybrid/hybrid_reranker), узел query_transformation не требуется, так как агент будет сам формировать поисковые фразы для вызова инструмента

Мы модернизируем наш проект:
- оформляем наш ретриевер в виде tool с описанием инструмента, аргументов и возвращаемых значений
- текущий Evaluation RAG должен продолжать функционировать для этого нужно сохранить в результатах перечень использованных для ответа документов
- точка входа теперь ии-агент с перечнем инструментов и системным промптом в котором есть четкая инструкция в каком случае вызывать данный инструмент, приведены few-shot примеры и даны подсказки по использованию инструмента

## Важные указания по реализации:
- Опирайся на референсную тетрадку docs/references/agent.ipynb , в части подхода к обертке инструмента tool, документированию описания и аргументов, а также создания ии-агента используя create_agent из LangChain 1.0 (раздел 10 тетрадки)
- Поддерживай модульную организацию кода
- Обязательные технологии: Python, uv для управления зависимостями и вирт окружением, make для сборки проекта, для интеграции с Telegram Bot API используй async aiogram и метод polling
- LLM-провайдер: OpenRouter (OPENAI_BASE_URL=https://openrouter.ai/api/v1)
- СОЗДАНИЕ АГЕНТА: Используй create_agent() из LangChain 1.0 с MemorySaver.
- ИНСТРУМЕНТ RAG_SEARCH: Возвращай {"sources": [...]}. Каждый source содержит: source (имя файла), page_content (полный текст - обязательно для RAGAS), page (номер страницы только для PDF). Используй ensure_ascii=False.
- ПОЛУЧЕНИЕ ОТВЕТА: В agent_answer используй bank_agent.stream() с stream_mode="values". Создай функцию для логирования каждого шага. Добавь warning при пустом AIMessage без tool_calls. Fallback для пустых ответов обязателен.
- ИЗВЛЕЧЕНИЕ ИСТОЧНИКОВ: Функция извлечения источников из текущего ответа должна собирать documents только после последнего HumanMessage (текущий запрос, не вся история). Собирай все ToolMessage с rag_search из текущего запроса.
- EVALUATION: Функция evaluate_dataset() полностью async. Внутри async def target(). Правильное использование aevaluate: сначала experiment_results = await client.aevaluate(...), потом async for result in experiment_results. Для RAGAS contexts извлекай page_content из documents. Уникальный chat_id присваивай каждому вызову, так как у нас история диалога храниится в MemorySaver.
