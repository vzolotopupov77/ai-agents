# Идея: Интеллектуальный ассистент для банковского обслуживания

## Описание проекта

Telegram-бот для автоматизации консультаций клиентов банка по продуктам и услугам. Бот построен как ReAct-агент: он самостоятельно рассуждает над вопросом и решает, когда нужно искать в документах через инструмент `rag_search`, а когда можно ответить напрямую.

## Бизнес-задача

**Проблема:**
- Клиенты задают много повторяющихся вопросов о кредитах, вкладах и условиях обслуживания.
- Операторы тратят время на поиск информации в объёмных документах.
- Нужна круглосуточная поддержка.

**Решение:**
Интеллектуальный ассистент, который:
- Мгновенно отвечает 24/7.
- Ищет нужное в документах банка через `rag_search` только когда это действительно нужно.
- Понимает контекст диалога и уточняющие вопросы.
- Опирается на актуальные документы, а не на параметрическую память LLM.

## Ключевые возможности

### Для клиентов

**Естественный диалог:**
- Клиент задаёт вопросы обычным языком в Telegram.
- Бот понимает контекст беседы и помнит предыдущие сообщения (через MemorySaver).
- Можно задавать уточняющие вопросы без необходимости повторять контекст.

**Примеры диалога:**
```
👤 Какие условия потребительского кредита?
🤖 Кредит от 30 000 до 5 000 000 ₽ на срок 3–60 мес.,
   ставка 12.9–19.9% годовых.

👤 А можно досрочно погасить?
🤖 Да, без комиссий.
```

**Прозрачность источников:**
- Опционально показывает имя файла и страницу, откуда взята информация.

### Для бизнеса

**Автономность (ReAct Agent):**
- Паттерн ReAct: Reason → Act → Observe → Respond.
- Агент сам выбирает стратегию: когда искать в документах, когда отвечать напрямую.
- Инструмент `rag_search` вызывается только при необходимости — не на каждое сообщение.
- Адаптируется к разным типам вопросов без жёстких сценариев.

**Качество обслуживания:**
- Консистентные ответы на основе официальных документов.
- Нет риска устаревшей информации — обновили PDF, бот сразу использует новые данные.
- Несколько режимов поиска (semantic / hybrid / hybrid + reranker) под разный баланс качества и скорости.

**Масштабируемость:**
- Обслуживает много клиентов одновременно (async).
- Новые документы — просто положить PDF в `data/`.

### Для управления

**Мониторинг и контроль:**
- LangSmith трейсинг показывает каждый шаг ReAct-цикла и каждый вызов `rag_search`.
- Видно, на каких вопросах агент звал инструмент, а на каких ответил напрямую.

**Оценка качества:**
- Автоматический синтез датасетов из документов.
- RAGAS-метрики: faithfulness, answer relevancy, answer correctness, answer similarity, context recall, context precision.
- Сравнение режимов retrieval по метрикам.

## Эволюция функционала

### Этап 1: Базовый LLM-бот ✅
- Простой Telegram-бот с историей диалога.

### Этап 2: RAG-ассистент ✅
- Индексация PDF, ответы на основе документов.
- Query transformation для уточняющих вопросов.

### Этап 3: Мониторинг и оценка ✅
- LangSmith трейсинг.
- Синтез датасетов и RAGAS-evaluation прямо из бота.

### Этап 4: Advanced Hybrid RAG ✅
- Три режима retrieval: semantic, hybrid, hybrid + reranker.
- Конфигурируемые embeddings: OpenAI / HuggingFace.

### Этап 5: ReAct-агент ✅
- Точка входа — `create_agent()` (LangChain 1.0) с MemorySaver.
- RAG обёрнут в инструмент `rag_search` (`@tool`).
- Агент сам формулирует поисковый запрос (узел `query_transformation` больше не нужен).
- Источники собираются только из текущего turn — для отображения и для RAGAS.

## Сценарии использования

- Условия кредитов и вкладов, процентные ставки, требования к заёмщикам.
- Открытие счетов и карт, переводы, тарифы.
- Часто задаваемые вопросы и разъяснение договоров.
